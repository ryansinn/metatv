## What this implies for the cleanup

1. **Attach a guard to every cleanup item, or skip the item.** The evidence is unambiguous: guarded
   findings are at zero two months later; unguarded ones doubled. A "tidy up the big files" pass
   with no ratchet will read as done and be back within two releases.
2. **A line-count ratchet is the cheapest guard available** — a test that fails when any file grows
   past its current size, allowing shrink but not growth. That converts a one-time cleanup into a
   standing invariant without dictating any particular split.
3. **`channel.py` is the highest-value split and it is NOT UI work** — it can proceed in parallel
   with, or ahead of, the overhaul without touching it.
4. **The widget-layer debt that actually collides with the overhaul** is `main_window.py` (3173),
   `main_window_channels.py` (2009), `details_sections.py` (1860) and `global_filter_dialog.py`
   (1747). That is the subset worth doing *first* if the overhaul is next.
5. **`get_session()` growing is a rule-adherence failure, not a backlog item.** New code is still
   choosing the legacy form despite the rule; that is cheap to ratchet the same way.
